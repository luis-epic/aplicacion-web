# Observabilidad y recuperación operativa listas para producción (v3)

El cambio incorpora correlación W3C, logs JSON sanitizados, métricas RED protegidas y readiness de PostgreSQL, conectados con Compose endurecido y procedimientos de despliegue, backup, restore, TLS, incidentes y rotación. La instrumentación HTTP se instala antes de los parsers de body y el edge field bloquea las dos formas aceptadas de `/metrics`, cerrando los bloqueantes de v2. La retención opera sólo sobre pares dump/checksum verificados y el checkpoint pre-migración precede a cualquier `up` que pueda ejecutar migraciones. La cobertura automatizada queda fuera de alcance en #13.

**Verdict**: APROBADO

## High-level view

`RequestContextMiddleware` abre RED antes de consumir el body. `aborted`, `finish` y `close` convergen en un cierre idempotente, cubriendo parser, guardas, controladores, 404, throttling y desconexiones con el estado final.

Métricas exige un token dedicado y compara digests SHA-256 de longitud fija. Nginx field devuelve 404 para `/api/v1/metrics` y `/api/v1/metrics/`; los logs excluyen contenido HTTP sensible y sanitizan claves y patrones de credenciales.

Compose separa edge, aplicación y datos, publica HTTP sólo en loopback, monta secretos por archivo y limita capacidades, recursos y logs. Readiness conserva la causa PostgreSQL sólo en el canal interno sanitizado; shutdown hooks, `init` y periodos de gracia alinean el ciclo de vida.

Backup vuelve a verificar el conjunto restaurable y cancela la retención ante huérfanos o alteraciones. Restore valida checksum y catálogo y opera transaccionalmente; despliegue sitúa el checkpoint y su copia off-host antes de migraciones.

TLS del edge, scraper/alertas, scheduler y almacenamiento cifrado e inmutable off-host son controles explícitos de la plataforma elegida, no garantías fingidas por el Compose vendor-neutral.

## RED desde la entrada HTTP hasta el cierre real

El bootstrap deshabilita el parser implícito de Nest, registra `RequestContextMiddleware` y después instala parsers Express con límite de 100 KB. `request.aborted`, `response.finish` y `response.close` llaman al mismo observador protegido por `observed`: los abortos quedan como `499` y las respuestas terminadas usan `response.statusCode`. La ruta se reduce a la plantilla resuelta o `unmatched` y el método a un catálogo fijo, sin IDs ni URL solicitada en labels.

La correlación acepta UUID y `traceparent` v00 válidos y genera IDs criptográficos para entradas inválidas. El filtro global conserva los contratos de `HttpException`, añade el identificador y evita detalles internos en 500; readiness registra la excepción original mediante el sanitizador antes de devolver un 503 opaco.

## Token de métricas y aislamiento del edge field

`METRICS_ENABLED=true` exige un secreto de al menos 32 caracteres. `MetricsGuard` procesa Bearer sin sensibilidad a mayúsculas y compara hashes SHA-256 mediante `timingSafeEqual`; producción recibe el token desde un archivo de secreto y publica la API sólo en `127.0.0.1`.

Nginx field define ubicaciones exactas para `/api/v1/metrics` y `/api/v1/metrics/` antes del proxy `/api/`. Los smokes devolvieron 404 en ambas variantes y `ready=200`; el token permanece como defensa adicional.

`StructuredLoggerService` redacta claves sensibles estructuradas, Bearer, JWT, credenciales de URL y formas key/value en mensajes o stacks. El access log no captura body, query string, cookies ni cabeceras.

## Topología Compose, secretos y apagado

PostgreSQL permanece sólo en `data`; API une `edge`, `app` y `data`, web une `edge` y `app`, y field sólo `edge`. Los puertos HTTP se vinculan a loopback. Los contenedores usan filesystem de sólo lectura, tmpfs acotados, `no-new-privileges`, capacidades eliminadas, límites de recursos y rotación `json-file`.

`api-migrate` espera PostgreSQL healthy y debe completar antes de API; web espera API ready. La API habilita shutdown hooks y Prisma desconecta durante el cierre. El build web rechaza una API HTTP salvo la excepción MVP explícita y restringida a loopback.

Los secretos de base, JWT y métricas se cargan desde archivos. La validación rechaza JWT iguales, secretos de ejemplo, token de métricas ausente y orígenes HTTP en producción; el runbook exige que `TRUST_PROXY_HOPS` coincida con proxies controlados.

## Backup restaurable antes de migrar

El backup transmite `pg_dump` custom a un archivo nuevo, elimina resultados parciales y escribe SHA-256. Antes de podar recalcula cada checksum, aborta ante cualquier dump huérfano, alterado o no verificable y sólo entonces protege los `MinimumBackups` válidos más recientes y elimina pares completos fuera de plazo.

Restore exige confirmación, `.sha256`, catálogo válido y ejecuta `--clean --if-exists --exit-on-error --single-transaction`. El runbook retira escritores y tráfico, crea un backup de la base actual y exige readiness y flujos críticos antes de reabrir.

`deployment.md` exige crear, verificar y copiar externamente el checkpoint antes de `docker compose up -d`, donde `api-migrate` puede modificar la base. Backup diario, alertas, retención externa, cifrado/inmutabilidad y simulacros trimestrales quedan como obligaciones operativas concretas con RPO 24 h y RTO 4 h.

## Validación ejecutable del paquete

API, field y web pasan typecheck, lint y build; `git diff --check main` no detecta errores. Los Compose MVP y producción pasan `docker compose config --quiet`. Contra los servicios activos, `/health/live` y `/health/ready` devolvieron 200 con correlación y field devolvió 404 para ambas variantes de métricas. El smoke aportado de aborto durante body parser produjo `499`, consistente con el orden y cierre verificados; la imagen API reconstruida quedó healthy. No se exige automatizar estos casos porque corresponde a #13.
