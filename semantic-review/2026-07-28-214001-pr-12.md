# Observabilidad y recuperación operativa corregidas (v2)

La revisión corregida mueve RED al ciclo HTTP de middleware, conserva etiquetas acotadas, endurece el token de métricas y alinea backup, despliegue y URL pública con las garantías operativas pedidas. Los estados finales de controlador, guardas, 404 y throttling se verificaron en ejecución, y las correcciones de retención, checkpoint, redacción y readiness están presentes en código. Persisten dos huecos en los límites del transporte: un aborto durante el parseo del body queda fuera de RED y la variante con barra final de `/metrics` atraviesa Nginx field. Off-host, TLS del edge y backend de monitoreo quedan correctamente descritos como activaciones externas, no como implementación local pendiente en este diff.

**Watch for:** **[BLOQUEANTE, confirmado]** los abortos durante la lectura del body no llegan al middleware y no producen contador `499`; **[BLOQUEANTE, confirmado]** `GET /api/v1/metrics/` evita el bloqueo exacto de Nginx field y alcanza la API.

**Verdict**: **NEEDS_CHANGES**

## High-level view

`RequestContextMiddleware` abre RED antes de guardas/controladores y cierra sobre `finish` o `close`; la bandera `observed` evita doble conteo y la ruta se reduce a la plantilla resuelta o `unmatched`. El smoke test produjo series separadas `400`, `401`, `404` y `429` con rutas estables, pero una conexión cortada mientras Express aún leía un body incompleto no produjo ninguna serie porque ese parseo ocurre antes del middleware de módulo.

La credencial de métricas se compara mediante SHA-256 y `timingSafeEqual` sobre buffers de longitud fija. La ruta field bloquea sólo la forma exacta sin barra; la forma `/api/v1/metrics/`, aceptada por Nest, entra en el proxy general y conserva el token como única defensa.

La retención recalcula SHA-256 de cada dump, sólo cuenta pares válidos y aborta ante huérfanos o alteraciones antes de eliminar. El runbook coloca el checkpoint verificado y su copia externa antes de `up -d`, de modo que `api-migrate` ya no precede al punto de recuperación.

El Dockerfile web rechaza `NEXT_PUBLIC_API_URL` sin HTTPS y sólo permite HTTP cuando el flag explícito del Compose MVP apunta a `localhost` o `127.0.0.1`. El logger redacta credenciales key/value dentro de texto libre y readiness registra el error original a través del mismo sanitizador antes de responder con un 503 opaco.

## RED cubre estados finales pero empieza después del parseo del body

El cambio registra la finalización desde `RequestContextMiddleware`: `finish` usa `response.statusCode`, `close` clasifica como `499` cuando la respuesta no terminó y `observed` hace idempotentes ambos callbacks. `routeLabel` sólo acepta `request.route.path` o `unmatched`, y el método se limita a un catálogo fijo; no se incorporan URL, query, IDs ni request IDs a las labels. El smoke test produjo:

```text
opeconca_http_requests_total{method="POST",route="/api/v1/auth/login",status_code="400"} 1
opeconca_http_requests_total{method="GET",route="/api/v1/users",status_code="401"} 1
opeconca_http_requests_total{method="GET",route="unmatched",status_code="404"} 2
opeconca_http_requests_total{method="GET",route="/api/v1/health/live",status_code="429"} 5
```

**[BLOQUEANTE, confirmado]** un cliente raw envió `POST /api/v1/auth/login` con `Content-Length: 1000000`, entregó sólo `{` y cerró la conexión. No apareció ninguna serie `499` ni aumentó otra serie de esa petición. El body parser de Nest/Express consume y rechaza ese tráfico antes de que el middleware configurado por `ObservabilityModule` ejecute `requestStarted`; por tanto, in-flight y RED omiten abortos durante ingestión. La instrumentación debe registrarse antes de los parsers globales —o el bootstrap debe ordenar explícitamente contexto/RED antes del body parser— y cerrar una sola vez sobre `finish`/`close`.

## El bloqueo field admite una variante equivalente de `/metrics`

`MetricsGuard.matchesToken` calcula SHA-256 para candidato y secreto y siempre compara dos digests de 32 bytes con `timingSafeEqual`; también acepta el esquema Bearer sin sensibilidad a mayúsculas.

**[BLOQUEANTE, confirmado]** `nginx-field.conf` declara `location = /api/v1/metrics`, mientras Nest acepta también la barra final. El smoke test devolvió `404` para `/api/v1/metrics` pero `401` de la API para `/api/v1/metrics/`, demostrando que la segunda forma cayó en `location /api/` y fue proxyfiada. Nginx field debe negar ambas formas, por ejemplo con dos ubicaciones exactas o una regla que cubra `^/api/v1/metrics/?$`, dejando el token como defensa adicional y no como sustituto del aislamiento.

## Diagnóstico interno sanitizado y garantías antes del punto de riesgo

`StructuredLoggerService` redacta claves sensibles estructuradas y patrones key/value como `password=...`, `token: ...`, secretos, API keys, authorization y cookies, además de Bearer, JWT y credenciales embebidas en URL. `HealthController.ready` conserva la excepción de Prisma en `postgres_readiness_failed`; el logger la reduce a nombre, mensaje y stack sanitizados, mientras el cliente recibe únicamente el 503 opaco y el identificador de correlación.

La poda construye `validBackups`, recalcula cada hash y cancela toda retención si encuentra dump sin checksum, checksum inválido o archivo no verificable; `MinimumBackups` se aplica después sobre ese conjunto restaurable. `deployment.md` exige crear, verificar y copiar el checkpoint antes de `docker compose up -d`, donde `api-migrate` puede modificar PostgreSQL, y ordena abortar ante cualquier fallo.

`Dockerfile.web` exige HTTPS y sólo admite la excepción local con `ALLOW_INSECURE_LOCAL_API=true`; el único consumidor del flag es `compose.mvp.yaml` con `http://localhost:4000/api/v1`. La copia cifrada off-host, el edge TLS y el scraper/alertas se mantienen como activaciones explícitas del proveedor con controles y evidencias descritos en los runbooks.

Se ejecutaron typecheck, lint y build de API, `git diff --check`, y validación de los Compose MVP y producción; todos pasaron. Los smoke tests fueron comprobaciones manuales de esta revisión, no una exigencia de pruebas automatizadas, que corresponde a #13.
